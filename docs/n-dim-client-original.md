# n次元クライアントについて

## 概要

VR/Web でのアクセスを前提とした、新しい VR システムの構想について記します。

## 概念・コンセプト

- クライアントアプリケーションは高次元空間を低次元に写像する装置と考える。
  ここでの高次元空間には例えば座標、時間、セッション、物体の変形量、といった一般的な VR SNS に必要なすべての次元を備える。
- 写像関数はユーザーが定義することができる(UserGeneratedContent)し、一般的な用途に合わせてテンプレートが用意される。たとえばボイスチャットであり、例えばVR SNSであり、たとえば TRPG セッションのためのテーブルである。
- 高次元空間上に配置された空集合はエンティティと呼ぶ。
- この空間を観測できる存在をリーダ(Reader)と呼ぶ。リーダはこの世界のすべての次元について値を変更することはできない。
- この空間上でエンティティを操作（生成・削除・変更を含む）できる存在はライタ(Writer)と呼ぶ。
- クライアントアプリケーションはリーダから情報を受取り、ライタにユーザからの指示を伝えるシェルである。
- リーダ・ライタのスコープ（取り扱い可能な次元・値域）はセキュリティモデルにより制約を受ける。
- ユーザは自作したプログラムを送り込める(UserGeneratedContent)。
- ユーザーのプログラムは別途サーバーに用意された実行基盤上で動作する。
- プログラムにはリーダ・ライタへの接続が渡されるので、これを通して空間を観測・操作できる。もちろんセキュリティモデルによる制約を受ける。
- プログラムはインターネットへの接続性が提供されるので、システム外からの観測・操作を受けることができる。

## 実装

- データは超高速のデータベースに格納される。このデータベースは最適化のため、部分空間である座標とセッションの組を特別視しているかもしれない。
- リーダはこのデータベースに対してクエリを発行できる。また部分空間を指定して変更を配信するように要求できる。
- このデータベースは負荷分散のため、空間を動的に分割して責任を持つ空間ごとに並列動作できる。
- このデータベースは負荷分散のため、リードレプリカを配置できる。
- ライタはこのデータベースに対してクエリを発行して書き込むことができる。書き込まれた結果がリーダによって要求されている場合には配信される。

## 詳細な実装

- データベースは BeamVM 上で動作することを考える。責任を持つ空間ごとに1プロセス。
- リーダ・ライタは BeamVM 上で動作し、クライアントアプリケーションごとにそれぞれ複数のプロセスが起動する。
- プログラムは WASM 実行環境上で動作し、原則としてプログラムごとにリーダ・ライタが1プロセスずつ割り当てられる。
